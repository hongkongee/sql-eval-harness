# 키워드 추출 비교: 새 정답셋 100 (파인튜닝 GLiNER vs LLM)

- 작성일: 2026-11-04
- 질문: 파인튜닝 GLiNER가 **학습 때 한 번도 보지 못한 의료 컨셉**에서도 LLM만큼 키워드를 뽑는가
- 비교 대상: [09](09_키워드%20추출%20비교%20(파인튜닝%20GLiNER%20vs%20LLM).md)·[10](10_키워드%20추출%20비교%20—%20패러프레이즈%20573%20(파인튜닝%20GLiNER%20vs%20LLM).md)과 같은 파인튜닝 GLiNER(threshold 0.5)와 LLM
- 테스트셋: 이번에 새로 만든 100문장(N001~N100). **정답 의료 컨셉 227개가 모두 학습 데이터에 없다**(2절). 문장마다 사람이 정답을 검토해 확정했다
- 왜 새로 만들었나: 50문장 셋(09)은 정답 컨셉의 42%가, 패러프레이즈 셋(10)은 94%가 학습 데이터에 있었다. 10에서 처음 보는 컨셉의 재현율이 77.5%로 떨어졌지만 표본이 40개뿐이었다

세 셋을 나란히 놓으면 다음과 같다.

|---|---|---|---|

| 의료 컨셉 재현율: 파인튜닝 GLiNER / LLM | 90.1 / 98.8 | 95.4 / 99.2 | **83.7 / 100.0** |
| 의료 컨셉 F1: 파인튜닝 GLiNER / LLM | 92.4 / 94.7 | 97.2 / 94.3 | **88.0 / 97.6** |
| 스키마 F1 (겹침 인정): 파인튜닝 GLiNER / LLM | 87.9 / 85.8 | — (정답 없음) | **83.5 / 82.9** |
| 방문 유형·성별: 파인튜닝 GLiNER / LLM | 18 / 16 (23개) | 25 / 23 (25개) | **22 / 27 (30개)** |
| 다운스트림 추론 포함 커버리지: 파인튜닝 GLiNER / LLM | 80% / 90% | 94.6% / 98.8% | **67% / 99%** |

**결론.** 학습 데이터에 없는 컨셉에서는 파인튜닝 GLiNER가 LLM보다 확실히 떨어진다.
1. **의료 컨셉을 6개 중 1개꼴로 놓친다** (37 / 227). LLM은 하나도 놓치지 않았다. 학습 데이터와 겹칠수록 점수가 높았던 흐름(94% 겹침 95.4 → 42% 겹침 90.1 → 0% 겹침 83.7)이 그대로 이어진다.
2. **가장 약한 곳은 시술명이다** (27 / 45, 60%). 영문 약어(TAVI, CABG, ECMO, CRRT, ERCP, CPR), 중환자 처치(기계환기, 기관 삽관), 이식(간이식, 신장이식), 영상(심초음파, 복부 초음파)이다. 09에서도 시술명이 약점(5 / 9)이었는데, 이번 셋에서 더 분명해졌다.
3. **라벨도 틀린다** (11개, LLM 0개). 심초음파·복부 초음파·허리둘레·심박수·세프트리악손을 진단명으로 붙였다. 이 때문에 다운스트림 추론으로 정하는 테이블도 틀어진다.
4. 그 결과 **SQL에 필요한 테이블을 다 가리킨 문장이 67%** 뿐이다(LLM 99%). 엔진 입장에서는 이 차이가 가장 크다.
5. **스키마 키워드는 LLM과 비슷하고, 속도는 여전히 2배 빠르다.** 스키마 단어는 종류가 정해져 있어 학습 데이터와 겹치기 때문이다(2절).

그래서 파인튜닝 GLiNER를 LLM 대신 쓰려면 **처음 보는 의료 컨셉, 특히 시술명의 일반화를 먼저 올려야 한다**(6절).

**추가 테스트 (2026-11-06).** threshold를 0.5에서 0.3으로 낮춰도 놓친 컨셉은 하나도 돌아오지 않았다. 의료 컨셉 F1이 88.0에서 88.9로 오른 것은 라벨 2개가 바로잡힌 덕분이다(3.6절). threshold로는 시술명 놓침을 풀 수 없다. 파인튜닝 전 제로샷 모델은 시술명을 더 많이 잡았지만(35 / 45), 다른 라벨이 크게 떨어져 전체로는 훨씬 낮다(3.7절).

## 1. 테스트 조건

- **파인튜닝 GLiNER:** 09 1.1절과 같다. `POST <파인튜닝 서버>/keyword-extraction/llm-compat`, threshold 0.5, 사내 서버 CPU, 순차 호출.
- **LLM:** 09 1.2절과 같은 모델·프롬프트(sha256 `1bb9b021…`), temperature 0, thinking 끔, **순차 호출**.
- 두 모델을 같은 시간대에 함께 돌렸다. 실패는 둘 다 0 / 100.
- 채점은 09·10과 같은 채점기(`eval.csv_keyword_eval score`)다. 방문 유형·성별은 llm-compat 형식에서 스키마 항목으로 오기 때문에 10과 같은 방식으로 따로 셌다.

## 2. 정답셋

### 2.1 만든 방법

- Claude가 문장과 정답 초안을 만들고, 사람이 문장마다 검토해 확정했다(2026-11-04).
- 정답 형식과 열은 50문장 셋과 같다. 판단 근거는 CSV의 `note` 열에 남겼다.
- 파일: `test_set/keyword_ext/kw100/` (정답 CSV, 원본 `build.py`, 정답 규칙을 적은 README, 검토 목록)

### 2.2 학습 데이터와의 겹침

| 항목 | 결과 |
|---|---|
| 정답 의료 컨셉 227개 중 학습 데이터 정답 span에 있는 것 | **0** |
| 학습 문장에 그대로 나오는 것 | 0 |
| 학습 컨셉(3글자 이상)을 안에 포함하는 것 | 0 |
| 학습 문장과의 4글자 단위 유사도 | 중앙값 0.02, 최대 0.23 |
| 50문장 셋과의 4글자 단위 유사도 | 최대 0.25 |

- 스키마 단어(환자, 진단, 처방…)와 방문 유형·성별 단어(입원, 외래, 여성…)는 종류가 정해져 있어 학습 데이터와 겹칠 수밖에 없다. 그래서 이 셋이 "처음 보는 것"을 재는 것은 **의료 컨셉만**이다.

### 2.3 구성

- 의료 컨셉 227개: 진단명 91, 약물명 58, 시술명 45, 검사명 33
- 방문 유형 16, 성별 14
- 스키마 키워드 214개
- case_type: 기본형 24, 영문약어 17, 스키마단어없음 13, 사전누락 10, 경계사례 10, 복합 8, 구어체 6, 함축 5, 동의어 3, 연구설계 2, 오탐유도 2

### 2.4 검토에서 정한 정답 규칙

50문장 셋의 기준을 따르되, 검토 중에 아래를 정했다. 전체 규칙은 `kw100/` README에 있다.

- **테이블을 가리키는 단어는 스키마로 넣는다.**
  - 투약 표현: 주사, 약, 약물 이름 뒤의 치료·요법 ("펨브롤리주맙 치료", "병용 요법")
  - 컨셉 이름 안의 수술·치료: "방사성 요오드 치료", "물리치료" → 치료
  - 시술명 뒤의 검사·촬영: "PET-CT 촬영" → 촬영
  - 사람 명사: 아이·소아·영아·영유아·노인, 수혜자
- **넣지 않는 단어:** 시행, 기록, 이력, 날짜, 발생, 재발, 코호트, 시작한, 바꾼.
  - 재발은 SQL에서 "시술일 이후 같은 진단이 다시 나오는가"로 표현한다. OMOP CDM v5.3에는 재발 테이블이 없다.
- **원인이 붙은 진단명은 하나로 둔다** ("대상포진 후 신경통").

시술명이 가장 크게 떨어지고, **검사명도 소폭이 아니라 크게 떨어진다.** 진단명과 약물명은 소폭 떨어진다. LLM은 네 라벨 모두 100이다.

- **시술명 (60.0, 놓친 것 18개):** 학습한 시술명 밖으로는 거의 일반화하지 못한다.

  - 중환자 처치: 기계환기, 기관 삽관
  - 이식: 간이식, 신장이식
  - 영상·내시경: 심초음파 ×2, 복부 초음파, 기관지 내시경
  - 천자: 흉강 천자, 요추 천자, 골수 검사
- **검사명 (81.8, 놓친 것 6개):** AST, 허리둘레, 산소포화도, 심박수, 체중, 적혈구 용적률. AST를 빼면 **활력징후·신체 계측**이 대부분이다. 학습 데이터의 검사명(62건)은 혈압·콜레스테롤 같은 혈액 검사 수치가 중심인 것으로 보인다(확인 필요).
- **진단명 (90.1, 놓친 것 9개):** 건선, 완전 방실차단, 기흉, 대동맥 박리, 총담관결석, 지방간, 루푸스, 비만, 크룹. 희귀한 병이 아니라 흔한 질병도 놓친다.
- **약물명 (93.1, 놓친 것 4개):** 리튬, 세프트리악손, 리툭시맙, 항응고제. 네 라벨 중 가장 안정적이다.
- **놓친 37개 중 11개는 라벨 오류다.** 위치는 잡았지만 라벨이 틀렸다.
  - 진단명으로 붙인 것: 시술인 심초음파 ×2·복부 초음파, 검사인 허리둘레·심박수·적혈구 용적률, 약물인 세프트리악손
  - 그 밖: 시술인 골수 검사·기관지 내시경·PET-CT를 검사명으로, 진단인 총담관결석을 시술명으로 냈다
- 학습 데이터 예시가 적은 라벨(검사명 62, 시술명 138)일수록 대체로 많이 떨어진다. 다만 검사명은 예시가 가장 적은데도 시술명보다 덜 떨어져서 예시 수만으로 설명되지는 않는다.
- **LLM의 오탐 11개:** 측정값 ×2·수치·이상 소견을 검사명으로, 병용 요법·정맥 투여·응급 수술·주사를 시술명으로, 탈장·폐경 후를 진단명으로, 중심정맥관을 약물명으로 냈다. 50문장 셋(09 3.2절)과 같은 경향이다. 스키마 단어를 컨셉으로 한 번 더 내는 경우가 많다.

### 3.2 스키마 키워드

| 지표 | 파인튜닝 GLiNER | LLM |
|---|---|---|
| 정확 일치 P / R / F1 | 87.8 / 74.3 / 80.5 | 77.6 / 72.9 / 75.2 |

- 오탐의 상당수는 "여성", "남성", "응급실" 같은 방문 유형·성별 단어다. llm-compat 형식은 방문 유형·성별을 스키마 항목으로 보내기 때문에 생긴다(09·10과 같다).
- **파인튜닝 GLiNER가 놓친 것:** 사람 ×12, 수치 ×9, 치료 ×4, 맞은 ×3, 검사 ×3, 수술 ×3, 퇴원 ×2, 촬영 ×2 등. "사람"은 문장에 나와도 거의 내지 않는다(2번만 냄, 그중 1번은 table을 death로 붙임). 09·10에서도 같은 약점이 있었다.
- **LLM이 놓친 것:** 수치 ×7, 투여 ×5, 치료 ×4, 수술 ×4 등.
  - LLM의 정확 일치 정밀도가 낮은 것은 "투여한 기록", "처방 이력", "병용 투여 이력"처럼 길게 내기 때문이다. 겹침 인정에서는 차이가 줄어든다.
  - LLM만의 진짜 오탐은 기록 ×3, 코호트, 가임기, 산모, 발생, 재발 여부, 시행한 등이다. 정답 규칙에서 빼기로 한 단어들이다.
- 구어체(먹고, 맞은)·사전누락 유형에서는 둘 다 스키마 재현율이 50%대로 낮다.

| 두 모델의 스키마 키워드가 완전히 같은 문장 | 52 / 100 |

### 3.3 방문 유형·성별 키워드

| 지표 | 파인튜닝 GLiNER | LLM |
|---|---|---|
| 잡음 / 30 | 22 | **29** |
| 맞는 종류로 냄 / 30 | 22 | **27** |

- **파인튜닝 GLiNER가 놓친 것 (8개):** 응급실, 재원, 남아 ×2, 퇴원 ×2, 외래, 여환. 학습 데이터에 적은 변형 표현(재원, 퇴원, 남아, 여환)에서 많이 놓쳤다.
- **LLM:** 재원 하나만 놓쳤다. 퇴원을 "퇴원일"(속성)로, 여환을 환자(person 엔티티)로 낸 2개가 종류가 틀렸다.
- 09·10에서는 파인튜닝 GLiNER가 더 많이 맞혔다. 이번 셋에는 변형 표현을 일부러 넣어서 결과가 뒤집혔다. 표본이 30개라 차이는 대략적으로만 봐야 한다.

| 응답 그대로: 커버리지 | 18% | 18% |

- 다운스트림 추론(의료 컨셉 라벨 → 테이블)을 포함하면 LLM은 거의 다 맞는다. 파인튜닝 GLiNER는 **procedure_occurrence가 64.3%** 에 그친다. 시술명을 놓치거나 다른 라벨로 냈기 때문이다(3.1절).
- 다운스트림 추론 포함 커버리지는 09보다 차이가 커졌다(10%p → 32%p).

### 3.6 추가 테스트: threshold 0.3 (2026-11-06)

5절에서 "놓침(37)이 오탐(15)보다 많으니 threshold를 낮추면 재현율이 오를 수 있다"고 적었다. 이를 확인하려고 서버의 `FINETUNED_THRESHOLD`를 0.3으로 바꿔 재시작한 뒤 같은 100문장을 다시 돌렸다. 나머지 조건은 1절과 같다.

| 지표 | 0.5 (기존) | 0.3 |
|---|---|---|
| 의료 컨셉 P / R / F1 | 92.7 / 83.7 / 88.0 | 93.7 / 84.6 / 88.9 |
| 의료 컨셉 놓침 / 라벨 오류 | 37 / 11 | 35 / 9 |
| 스키마 F1 (정확히 일치) | 80.5 | 81.8 |
| 스키마 F1 (겹침 인정) | 83.5 | 84.8 |
| 방문 유형·성별 / 30 | 22 | 21 |
| 다운스트림 추론 포함 커버리지 | 67% | 66% |
| 응답 속도 평균 / 중앙값 | 0.47초 / 0.45초 | 0.47초 / 0.45초 |

| 라벨 | 0.5 | 0.3 |
|---|---|---|
| 진단명 | 82 / 91 | 82 / 91 |
| 약물명 | 54 / 58 | 54 / 58 |
| 검사명 | 27 / 33 | 28 / 33 |
| 시술명 | 27 / 45 | 28 / 45 |

- **새로 찾은 컨셉은 없다.** 점수가 오른 2개는 0.5에서도 키워드는 잡혔지만 라벨이 틀렸던 것이다. 0.3에서 라벨이 바로잡혔다.
  - 허리둘레: 진단명 → 검사명(정답)
  - PET-CT 촬영: 검사명 → 시술명(정답)
- **0.5에서 놓친 시술명(CABG, ECMO, CRRT, ERCP, 간이식, 기계환기 등)은 0.3에서도 하나도 나오지 않았다.** 모델이 이 단어들에 0.3보다 낮은 점수를 준다는 뜻이다. 그래서 놓침은 threshold 문제가 아니라 일반화 문제로 본다. 같은 시술명 상당수를 파인튜닝 전 제로샷 모델(threshold 0.2)은 잡았다.
- 새로 들어온 응답은 대부분 잡음이다.
  - "수치"(스키마, ATTRIBUTE) 5건
  - 루푸스를 약물명으로 냄(N080)
- **낮췄는데 오히려 사라진 응답이 5개 있다.** threshold만 바뀌었다면 원래 통과하던 응답은 그대로 남아야 한다. 같은 문장을 다시 호출해도 똑같이 빠졌다. 원인은 아직 모른다. 재시작 때 다른 설정(모델 경로 등)도 함께 바뀌었는지 확인이 필요하다.

  | 문장 | 사라진 응답 |
  |---|---|
  | N020 | 만 6세에서 12세 (스키마) |
  | N033 | 소아 (스키마) |
  | N092 | 주사 (스키마) |
  | N096 | 응급실 (방문 유형). 방문 유형·성별이 22 → 21, 커버리지가 67% → 66%로 준 원인 |
  | N099 | 적혈구 (진단명, 원래 오답) |

- 정리: 0.3은 F1을 조금 올리지만 놓침은 그대로이고 잡음이 는다. **threshold 조정으로는 이번 셋의 핵심 문제(처음 보는 시술명 놓침)를 해결할 수 없다.** 다음은 학습 방법이다(6절).
- 이 결과로 threshold 값을 고르지는 않았다. 이 셋을 홀드아웃으로 남기려면 값은 다른 셋으로 골라야 한다.

### 3.7 비교: 제로샷 GLiNER vs 파인튜닝 GLiNER

파인튜닝이 무엇을 얻고 무엇을 잃었는지 보려고, 파인튜닝 전 원래 모델(제로샷)을 같은 100문장에 돌렸다.
- 엔드포인트: `POST <파인튜닝 서버>/keyword-extraction/llm-compat/zero-shot`(2026-11-04 실행)
  - 지금은 `/keyword-extraction/llm-compat?model=zero-shot`으로 바뀌었다. 서비스 코드상 같은 함수를 거친다.
- threshold: 0.2(서버 기본값 `LLM_COMPAT_ZEROSHOT_THRESHOLD`)
- 출력 형식과 채점은 파인튜닝 모델과 같다. 같은 라벨 목록(`llm_compat_map.yaml`)으로 한 번에 뽑는다.

| 지표 | 제로샷 (0.2) | 파인튜닝 (0.5) |
|---|---|---|
| 의료 컨셉 P / R / F1 | 57.7 / 66.1 / 61.6 | **92.7 / 83.7 / 88.0** |
| 의료 컨셉 놓침 / 라벨 오류 | 77 / 37 | **37 / 11** |
| 의료 컨셉 오탐 | 110 | **15** |
| 스키마 F1 (정확히 일치) | 51.8 | **80.5** |
| 스키마 F1 (겹침 인정) | 60.5 | **83.5** |
| 스키마 오탐 | 195 | **22** |
| 방문 유형·성별 / 30 | 19 | **22** |
| 다운스트림 추론 포함 커버리지 | 64% | **67%** |
| 응답 속도 평균 / 중앙값 | 0.47초 / 0.45초 | 0.47초 / 0.45초 |

| 라벨 | 제로샷 | 파인튜닝 |
|---|---|---|
| 진단명 | 58 / 91 | **82 / 91** |
| 약물명 | 45 / 58 | **54 / 58** |
| 검사명 | 12 / 33 | **27 / 33** |
| 시술명 | **35 / 45** | 27 / 45 |

- **파인튜닝으로 얻은 것:** 시술명을 뺀 모든 지표가 크게 올랐다. 특히 오탐이 크게 줄었다(의료 컨셉 110 → 15, 스키마 195 → 22). 라벨 판단도 정확해졌다(라벨 오류 37 → 11). 제로샷은 같은 위치에 키워드는 잡아도 라벨을 자주 틀린다.
- **파인튜닝으로 잃은 것: 시술명.** 제로샷이 35 / 45로 파인튜닝(27 / 45)보다 높은 유일한 라벨이다.
  - 파인튜닝이 놓친 37개 중 13개를 제로샷이 잡았다: CABG, 골수 검사, 요추 천자, 간이식, ECMO, 기계환기, CRRT, ERCP, CPR, PET-CT, 기흉, 허리둘레, 항응고제
  - 원래 모델이 알던 시술명을 학습 과정에서 잃은 것으로 본다. 학습 데이터의 시술명은 138건뿐이다.
  - 3.6절에서 threshold를 0.3으로 낮춰도 이 시술명들은 돌아오지 않았다. 파인튜닝 모델이 이 단어들에 매우 낮은 점수를 준다는 뜻이다.
- **방문 유형·성별:** 제로샷은 30개 위치에 모두 무언가를 냈지만, 맞는 종류·테이블은 19개다. "입원"을 환자(person)나 시술 테이블로 내는 식으로 틀렸다.
- **정리:** 제로샷을 그대로 쓸 수는 없다. 다만 파인튜닝이 시술명 일반화를 떨어뜨렸다는 근거가 된다. 그래서 다음 학습은 원래 지식을 덜 잃는 방향으로 간다. 학습 데이터에 없는 컨셉으로 검증셋을 따로 떼고, epoch을 줄인 체크포인트들을 비교한다(6절).

## 5. 이 비교의 한계

- **문장을 Claude가 만들었다.** 사람이 정답을 검토했지만, 문장 자체는 실제 운영 질의가 아니다. 문장이 짧고 정형화되어 있다(평균 30자 안팎).
- **같은 Claude가 문장과 정답 규칙을 만들었다.** LLM(Qwen)과 Claude의 표현 습관이 비슷해 LLM에 유리할 수 있다. 다만 의료 컨셉 정답은 이름 그대로라 영향은 작다고 본다.
- **스키마 단어와 방문 유형·성별은 처음 보는 것이 아니다.** 이 셋이 홀드아웃인 것은 의료 컨셉뿐이다.
- **표본:** 방문 유형·성별 30개, 시술명 45개로 크지 않다.
- **threshold:** 파인튜닝 GLiNER 0.5는 여전히 검증하지 않은 값이다. 0.3으로 낮춰 봤지만 놓친 컨셉은 돌아오지 않았다(3.6절).
- **조건 항목:** 이 셋에도 정답이 없다. GLiNER는 여전히 내지 않는다.

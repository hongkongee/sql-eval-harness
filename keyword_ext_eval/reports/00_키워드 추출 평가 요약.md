## 1. 목적과 목표

**목적.** 자연어 임상 질의에서 키워드를 뽑아 다운스트림 스키마 RAG와 concept RAG로 넘기는 단계의 성능을 숫자로 관리한다. 구체적으로 세 가지를 판단하는 근거로 쓴다.
1. 사전이나 코드를 바꾼 새 리비전이 실제로 나아졌는지, 회귀는 없는지
2. 지금 운영 중인 프롬프트 기반 LLM 대비 하이브리드 방식(사전 + GLiNER)이 어느 정도 수준인지
3. 다음에 무엇을 고쳐야 효과가 큰지 (경로별·테이블별 약점)

**목표 (안).** 정해진 기준선은 아직 없다. 아래는 지금까지 결과를 보고 잡은 제안값이니 논의해서 확정한다.

| 지표 | 목표 (안) | v2 현재 |
|---|---|---|
| 스키마 키워드 정밀도 | 95% 이상 유지 | 98.3% |
| concept(GLiNER) 재현율 | 90% 이상, 라벨별 80% 이상 | 91.4% (검사명 65%) |
| concept(Visit/Gender) 정밀도 / 재현율 | 95% 이상 / 80% 이상 | 100% / 52.2% |
| 테이블 커버리지 (최종 출력 기준) | 90% 이상 | 42% (대체 스키마 모의 시 84%) |
| 회귀 | 이전 리비전이 맞힌 문장을 새로 틀리지 않음 | v1 → v2 회귀 0 |

## 3. 정답셋

- `test_set/keyword_ext/keyword_eval_samples_50.csv`: 사람이 직접 만든 50문장. 유형(`case_type`)은 기본형 17, 사전누락 8, 스키마단어없음 5, 오탐유도 5, 경계사례 4, 동의어 3, 영문약어 3, 함축 3, 복합 1, 컬럼표현 1이다.
- 문장마다 다섯 가지 정답이 있다: 스키마 키워드, GLiNER concept(텍스트와 라벨), Visit/Gender concept(텍스트, 도메인, 값), 대체 스키마 묶음, 정답 테이블
- **⚠ 오염 관리.** v2 사전까지는 이 정답셋을 보지 않고 만들었다. v2 보고서의 FN 목록을 보고 사전을 고친다면, 그 뒤 리비전부터 이 셋은 **개발셋**으로 표시하고 성능은 새 held-out 셋으로 잰다. 결과표의 "정답셋 상태" 행에 기록한다.

## 4. 지표 설명

### 기본 용어

| 용어 | 뜻 |
|---|---|
| TP (맞힘) | 정답에 있는 것을 냈다 |
| FP (오탐) | 정답에 없는 것을 냈다 |
| FN (놓침) | 정답에 있는 것을 안 냈다 |
| 정밀도 P | TP / (TP + FP). 낸 것 중 맞은 비율. 낮으면 엉뚱한 것을 많이 낸다 |
| 재현율 R | TP / (TP + FN). 정답 중 찾은 비율. 낮으면 많이 놓친다 |
| F1 | P와 R의 조화평균. 둘 중 낮은 쪽에 끌려간다 |

### 경로별 지표

| 지표 | 무엇을 재나 | 맞힘 기준 |
|---|---|---|
| **스키마 키워드** | 사전 매칭이 테이블을 가리키는 단어("처방", "환자")를 찾는가 | 표면형이 정답과 같음 |
| 스키마 키워드 (겹침) | 위와 같되, 구 단위로 내는 LLM 비교용 | 정답 표현의 위치와 겹침. API는 위 지표와 같은 값이 나옴 |
| **concept (GLiNER)** | 질병·약물·검사·시술 이름을 찾고 라벨을 맞게 붙이는가 | 위치가 겹치고 라벨이 같음. 위치는 맞고 라벨만 틀리면 "라벨 오류"(FN 1 + FP 1) |
| **concept (Visit/Gender)** | 방문 유형(입원·외래·응급실)과 성별 값을 찾는가 | 위치가 겹치고 도메인이 같음. 값(입원/외래 구분)은 응답에 없어 아직 안 잼 |
| 대체 스키마 (모의) | concept 라벨을 묶음 단어로 바꿨을 때(약물명 → 처방, 방문 유형 → 방문) 정답 묶음과 맞는가 | 묶음 집합 비교. **API가 내지 않는 값을 평가 도구가 만들어 본 것** |

### 테이블 지표 (최종 목적에 가장 가까운 지표)

| 지표 | 뜻 |
|---|---|
| 테이블 P / R | 키워드가 가리키는 테이블과 정답 SQL이 쓰는 테이블을 (문장, 테이블) 쌍으로 비교 |
| **커버리지** | 정답 테이블을 **전부** 가리킨 문장의 비율. 하나라도 빠지면 그 문장은 SQL을 못 짠다고 본다 |
| 스키마만 | 지금 API 출력 그대로 (스키마 키워드 → 테이블) |
| 스키마 + 대체 (모의) | 대체 스키마까지 더했을 때. 대체 스키마를 API에 넣을지 판단하는 근거 |
| person 제외 | "환자"는 거의 모든 문장에 있지만 SQL에 person 조인이 필요 없는 문장이 많아 person FP가 크다. 그 영향을 뺀 값 |

## 6. 결론 (2026-10-28 기준)

1. **스키마 사전은 사전에 있는 단어는 거의 다 정확하게 잡는다** (P 98 / R 94). 놓친 것은 모두 사전에 없는 단어(퇴원, 진료, 남녀, 재원, 먹고)라 사전 범위 문제다.
2. **GLiNER는 개체 위치는 다 찾지만 라벨이 약하다.** 놓친 7개가 모두 라벨 오류이고, 그중 6개가 검사명이 진단명·약물명으로 붙은 경우다. threshold를 올려도 나아지지 않는다(0.5에서 F1 88.2).
3. **지금 API 출력만으로는 테이블 커버리지가 42%다.** 질병명·시술명만 있고 "진단"·"시술" 같은 스키마 단어가 없는 문장이 많기 때문이다(condition 34%, procedure 30%). **concept 라벨을 대체 스키마로 넘기면 84%가 된다.** 가장 효과가 큰 다음 개선이다(API 계약 변경이라 승인 필요).
4. **v2의 Visit/Gender 사전은 오탐 없이 동작한다** (P 100). 재현율은 52%다. 놓친 것은 형태 변형("응급실 내원", "외래에서")과 없는 어휘(여자, 여환, male, 퇴원, 재원)다. 다른 경로에 회귀는 없다.
5. **운영 LLM 대비: 스키마 단어는 API가, 의료 라벨과 방문·성별은 LLM이 낫다.** 스키마 (겹침) F1 96 vs 86, concept F1 89 vs 95(라벨 오류 7 vs 1), 방문·성별 도메인 맞음 52% vs 70%. 테이블 커버리지는 둘 다 concept → 테이블 단계 없이는 36~42%, 대체 스키마(모의)를 더하면 84% vs 90%다. 응답 시간은 API가 3배 빠르다. 운영 LLM 숫자는 테이블 카탈로그 대체본·thinking 끔 조건이라 운영 설정을 받으면 다시 잰다.

**다음 후보 (효과 큰 순서)**
1. 대체 스키마 (concept 라벨 → 묶음)를 API 출력에 추가: 커버리지 42% → 84% (모의)
2. Visit/Gender 사전 보강 (형태 변형, 어휘). 이 정답셋을 보고 고치면 개발셋으로 전환
3. 검사명 라벨 오류 대응 (라벨 문구 실험 또는 파인튜닝)
4. 운영 LLM 재평가 (운영 `_catalog()`와 thinking 설정 확인 후)

## 8. 새 평가를 추가하는 방법

1. 결과를 뽑고 채점한다 (`keyword_ext_eval/`에서):
   ```bash
   C=../test_set/keyword_ext/keyword_eval_samples_50.csv
   python -m eval.csv_keyword_eval extract --csv $C --out eval/outputs/kw50_api_v3.jsonl                     # API 새 리비전
   python -m eval.csv_keyword_eval extract --system prod-llm --csv $C --out eval/outputs/kw50_prod_llm.jsonl  # 운영 LLM
   python -m eval.csv_keyword_eval score --csv $C --pred eval/outputs/kw50_api_v3.jsonl --out-dir eval/runs/kw50_v3
   ```
2. 콘솔 출력과 `eval/runs/<이름>/kw50_scores.json`의 숫자를 5절 표에 새 열로 넣는다.
3. 직전 리비전과 문장별로 비교해 "리비전 간 변화" 행을 채운다. 회귀가 있으면 해당 문장 id를 적는다.
4. 상세 보고서 파일명은 다음 번호를 붙인다 (`07_…md`). 이 문서의 보고서 목록에도 한 줄 추가한다.
5. API 리비전이면 [API 리비전](01_API%20리비전.md)에 열을 추가하고, 상세 보고서를 따로 쓴다.
6. 6절 결론과 1절 "v2 현재" 열을 최신 리비전 기준으로 고친다.

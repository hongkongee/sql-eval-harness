# 나이 계산 오류 분석 (FT3 + RAG)

- 확인일: 2026-10-20
- 재현: `10.1.1.69:8080/nl2sql`, 질의 "당뇨병 환자의 평균 나이"

## 1. 증상

| 시도 | 생성 SQL (나이 부분) | 결과 |
|---|---|---|
| 1차 | `AVG(EXTRACT(YEAR FROM (as_of - birth_datetime)))` | 오류: `column "as_of" does not exist` |
| 2차 (self-repair) | `AVG(EXTRACT(YEAR FROM (DATE '2026-10-20' - birth_datetime)))` | 평균 나이 `0E-20` |

- API는 `success: true`를 반환하므로, 값이 틀린 것이 드러나지 않습니다.

## 2. 원인

학습 데이터의 나이 정답(`year_of_birth`)은 맞습니다. 원인은 RAG 재료와 학습 범위에 있습니다.

1. **RAG 재료에 `year_of_birth` 누락**
   - 학습 데이터의 나이 정답은 모두 `EXTRACT(YEAR FROM CURRENT_DATE) - p.year_of_birth`입니다(train 2,058건, val 204건).
   - RAG 재료의 person 테이블에는 `birth_datetime`만 있어서, 모델이 학습한 패턴을 쓸 수 없었습니다.
2. **`0E-20`**: 대신 쓴 `DATE - timestamp`의 결과는 PostgreSQL에서 일 단위 interval입니다(예: `20000 days`). 여기서 `EXTRACT(YEAR ...)`를 하면 항상 0이 나옵니다.
3. **`as_of` 오류**: 재료의 `기준일(as_of)`를 모델이 컬럼으로 해석했습니다. 학습 데이터에 이런 문구는 0건입니다.
4. **집계형 나이 질의 미학습**
   - 학습 데이터의 나이 질의는 모두 "N세 이상" 같은 조건이고, 평균 나이를 구하는 정답은 0건입니다.
   - `year_of_birth`를 쓰는 질의 561건 중 532건(95%)에 "현재 연도 기준" 문구가 있습니다.
   - 그래서 문구 없이 "평균 나이"만 물으면, `year_of_birth`를 재료에 넣어도 쓰지 않습니다(4장 A·T2). 1번만 고쳐서는 해결되지 않는 이유입니다.

참고:
- **연 나이 기준**: 학습 정답은 출생연도 차이로 계산합니다. 생일 전인 환자는 만 나이보다 1살 많게 잡히므로, 경계 연령에서 차이가 납니다(C04). 질의가 "현재 연도 기준"이면 맞는 계산이며, 만 나이가 필요한지는 요구사항에 따라 정할 문제입니다.
- **샌드박스 한계**: 샌드박스 DB의 `year_of_birth`는 보안상 이관에서 빠져 전원 0입니다(운영 DB에는 값이 있음). 그래서 나이 문항은 샌드박스의 결과값·EX로 검증할 수 없습니다. 정답과 답변이 둘 다 0값을 쓰므로 EX가 통과해도 의미가 없습니다.

## 3. 조치

| 우선순위 | 조치 | 대상 | 근거 |
|---|---|---|---|
| 1 | person 재료에 `year_of_birth`를 추가하고, 컬럼 설명에 나이 계산식 표기<br>`- year_of_birth (출생 연도) integer  [나이 = EXTRACT(YEAR FROM CURRENT_DATE) - year_of_birth]` | RAG 재료 조립 (즉시) | 평균 나이 해결, 조건 질의 정상 유지 (T9). 컬럼만 추가하면 해결 안 됨 (A) |
| 2 | 기준일 표기에서 `as_of` 제거 (기준일 줄 삭제) | RAG 프롬프트 (즉시) | `as_of` 오류 사라짐 (A·B) |
| 3 | 집계형 나이 질의(평균, 최고령 등)를 "현재 연도 기준" 문구가 없는 형태로 학습 데이터에 추가 | 학습 데이터 → 재학습 | 계산식을 줘도 "최고령 나이"는 틀림 (T9 재료). "N세 이상" 조건 질의는 문구 없이도 정상 (T4·T5) |
| 4 | 나이 문항은 샌드박스 EX 대신 SQL 형태로 검증 (`year_of_birth` 사용, 비교 연산자 등) | 평가 | 샌드박스 `year_of_birth` = 0 (2장 참고) |

- 질의에 "현재 연도 기준"을 자동으로 붙이는 방법(T10)도 효과는 있었습니다. 다만 사용자 질의를 고쳐야 하고 문구가 다양하면 적용이 어려워, 1번을 권장합니다.
- 1·2번은 바로 적용할 수 있는 수정입니다. T9 프롬프트가 1·2번을 함께 적용한 상태입니다. 모든 집계형 나이 질의를 해결하려면 3번(재학습)이 필요합니다.

별도 이슈: 같은 응답에서 "당뇨병"에 `434164 Glycosuria`(당뇨)가 선택됐습니다. 당뇨병 상위 개념이 후보 5개 안에 없었기 때문으로, concept RAG 검색을 따로 점검해야 합니다.

## 4. 수정 프롬프트 테스트

- 조건: FT3(`by-loss`, vLLM 8007) 직접 호출, 학습용 시스템 프롬프트, temperature 0, max_tokens 512, 각 1회
- nl2sql 서비스를 거치지 않았습니다. 서비스의 시스템 프롬프트와 self-repair는 반영되지 않습니다.
- 샌드박스 `year_of_birth`가 0이라, 결과값이 아니라 생성 SQL 형태로 판정했습니다.

### 4-1. 컬럼 추가·기준일 변경 (A·B)

| 프롬프트 | 변경 내용 | 생성 SQL (나이 부분) | 결과 |
|---|---|---|---|
| 현재 | 없음 | `AVG(EXTRACT(YEAR FROM (as_of - birth_datetime)))` | 실행 실패: `column "as_of" does not exist` |
| A | `year_of_birth` 추가 + 기준일 줄 삭제 | `AVG(EXTRACT(YEAR FROM (CURRENT_DATE - p.birth_date)))` | 실행 실패: `column p.birth_date does not exist` |
| B | `year_of_birth` 추가 + 기준일을 `기준일: 2026-10-20 (상대 날짜·나이 계산에 이 날짜 사용, 테이블 컬럼 아님)`으로 변경 | `AVG(EXTRACT(YEAR FROM (DATE '2026-10-20' - p.birth_datetime)))` | 실행 성공, 결과 `0E-20` |

결론:
- **컬럼 추가·기준일 변경만으로는 해결되지 않았습니다.**
  - 기준일 문구를 바꾸면 `as_of` 오류는 사라졌습니다.
  - 하지만 모델은 A·B 모두 `year_of_birth`를 쓰지 않았습니다. 대신 날짜 빼기 + `EXTRACT(YEAR ...)` 방식을 그대로 썼고, A에서는 없는 컬럼 `birth_date`를 만들어 냈습니다.

### 4-2. 원인 대조 (질의 유형·문구·프롬프트 형식)

| 테스트 | 프롬프트 형식 | 질의 | 결과 |
|---|---|---|---|
| T1 | 학습 형식 | 현재 연도 기준 65세 이상 골다공증 환자 | `year_of_birth` 사용 |
| T4 | 학습 형식 | 65세 이상 골다공증 환자 | `year_of_birth` 사용 |
| T5 | RAG 형식(A) | 65세 이상 당뇨병 환자 | `year_of_birth` 사용 |
| T2 | 학습 형식 | 골다공증 환자의 평균 나이 | 날짜 빼기, 실행 실패 |
| T3 | 학습 형식 | 골다공증 환자의 현재 연도 기준 평균 나이 | `year_of_birth` 사용 |
| T7 | RAG 형식(A) | 당뇨병 환자의 현재 연도 기준 평균 나이 | `AVG(EXTRACT(YEAR FROM CURRENT_DATE) - p.year_of_birth)` (올바른 SQL. 샌드박스 결과 2026세는 `year_of_birth`가 0이라서 나온 값) |

- T6(RAG 형식, "현재 연도 기준 65세 이상")은 T5와 결과가 같아 생략했습니다.
- T8(현재 프롬프트 그대로 + "현재 연도 기준 평균 나이")은 `AS_OF_DATE`를 써서 실행 실패했습니다. 기준일 문구를 지우는 조치 2의 근거가 하나 더 생긴 셈입니다.
- 학습 형식과 RAG 형식의 차이는 원인이 아닙니다. 질의 유형("평균 나이")과 문구("현재 연도 기준") 유무에 따라 패턴이 갈립니다.
- `year_of_birth`를 재료에 주고 질의에 "현재 연도 기준"이 있으면, RAG 형식에서도 올바른 SQL을 생성합니다(T7).

### 4-3. 재학습 없는 수정안 (T9·T10)

| 테스트 | 프롬프트 변경 (A 기준) | 질의 | 생성 SQL (나이 부분) | 판정 |
|---|---|---|---|---|
| T9 | `year_of_birth` 설명에 `[나이 = EXTRACT(YEAR FROM CURRENT_DATE) - year_of_birth]` 추가 | 당뇨병 환자의 평균 나이 | `AVG(EXTRACT(YEAR FROM CURRENT_DATE) - p.year_of_birth)` | ✅ |
| T10 | 질의에 "현재 연도 기준" 추가 | 당뇨병 환자의 현재 연도 기준 평균 나이 | `AVG(EXTRACT(YEAR FROM CURRENT_DATE) - p.year_of_birth)` | ✅ |
| T9 재료 | T9와 동일 | 65세 이상 당뇨병 환자 | `(EXTRACT(YEAR FROM CURRENT_DATE) - p.year_of_birth) >= 65` | ✅ |
| T9 재료 | T9와 동일 | 당뇨병 환자의 최고령 나이 | `MAX(p.year_of_birth) AS max_age ... GROUP BY p.person_id` | ❌ 출생연도를 나이로 사용, 환자별로 묶음 |

- T9는 평균 나이를 해결하고, 기존 조건 질의도 그대로 정상입니다. 그래서 3장 1번 조치로 채택했습니다.
- "최고령 나이"는 계산식을 줘도 틀립니다. 재료 수정만으로는 모든 집계형 질의를 해결할 수 없습니다(3장 3번).

# NL2SQL 어댑터 평가 — 변형 테스트셋

> 종합 보고서와 지표 설명: [00_overview.md](00_overview.md) · 학습셋 결과: [01_train.md](01_train.md) · validation 셋 결과: [02_val.md](02_val.md)

- **테스트셋:** 학습셋(`proposed_input_train`)과 validation 셋(`proposed_input_val`)의 시드를 네 가지 방식으로 변형한 파일 4개예요. 시드 1건당 방법별로 변형 1건을 만들었고, 시드 원본은 넣지 않았어요.
  - 원본 파일: `test_set/{paraphrase,restructure,slot,concept}.jsonl`
  - 평가용 사본: `test_set/eval_ready/` — 같은 id가 두 번 나오는 2건(`seed_528_test_restructure`, `seed_420_test_concept`)의 두 번째 행에 `_2`를 붙였어요. 그 밖의 내용은 원본과 같아요.
  - 결과 파일: `results/adapter_eval/variant/adapter_eval_<모델>_variant_<변형>.csv`
- **집계 대상:** base+시스템 프롬프트의 few-shot 시드(290·535·721·447·299)에서 나온 변형은 모든 모델에서 빼고 집계해요(val과 같은 기준).
- **원본과 짝지어 비교:** 모든 변형에는 원본 시드 id(`seed_id`)가 있어요. 같은 모델·같은 시스템 프롬프트로 평가한 원본 문항 결과(학습셋·val)와 짝지어 "원본은 맞혔는데 변형하니 틀린 문항 수"를 세요.
- **요청 조건:** 모든 모델이 같은 사용자 메시지(질의 + 재료)를 받고, 시스템 프롬프트만 달라요([요청 프롬프트 구성](00_overview.md#요청-프롬프트-구성)).
  - FT0·FT1·FT2·base: 파인튜닝 학습 때 쓴 시스템 프롬프트(학습 때 문구)
  - base+시스템 프롬프트: 직접 설계한 시스템 프롬프트(v2)
  - temperature 0, max_tokens 512. 이번 테스트는 여러 모델을 동시에 돌려서 응답 속도는 비교하지 않아요.

| 변형 | 바뀌는 것 | 집계 문항 (train 출처 / val 출처) |
|---|---|---:|
| 3.1 자연어 패러프레이즈 | 자연어만 (SQL은 원본 그대로, 재료는 바뀐 문장으로 다시 부착) | 568 (515 / 53) |
| 3.2 SQL 재구성 | 정답 SQL만 (자연어·재료는 원본 그대로) | 384 (337 / 47) |

## 1. 핵심 요약

1. **FT2가 모든 변형에서 가장 높아요.** EX는 패러프레이즈 90.3%, SQL 재구성 97.4%, 슬롯 치환 97.1%, concept_id 변형 92.9%예요. 다음으로 높은 FT1(76.1% / 81.5% / 51.4% / 72.3%)이나 base+시스템 프롬프트(73.8% / 75.0% / 60.9% / 66.5%)보다 15~46%p 높아요.
2. **FT2는 처음 보는 코드도 잘 옮겨 써요.** concept_id 변형에서 학습 때 본 적 없는 코드로 바뀐 215건 중 192건(89.3%)을 맞혔고, 바뀌기 전 코드를 쓴 문항은 0건이에요. concept_id 올바른 반영률도 98.5%예요. 랜덤화 학습의 목적(외우지 않고 재료의 코드를 옮겨 쓰기)과 맞는 결과예요.
3. **FT2의 약점은 문장 표현 변화예요.** 패러프레이즈에서 원본 대비 −4.9%p로 모든 모델 중 가장 많이 떨어졌어요(원본 맞힘→변형 틀림 42건). 틀린 42건 중 38건은 코드는 맞았고, 대부분 "…집계하시오", "그 사유를…"처럼 바뀐 표현을 따라 반환 컬럼을 다르게 만든 경우예요. 학습 데이터의 문장 틀에 맞춰진 영향으로 보여요. 그래도 EX 자체는 90.3%로 가장 높아요.
4. **FT1과 base+시스템 프롬프트는 변형에 강해요.** 원본 대비 FT1 −1.8~+0.8%p, base+시스템 프롬프트 −3.8~+4.6%p예요. FT1이 슬롯 치환을 뺀 세 변형에서 base+시스템 프롬프트보다 높아요.
5. **FT0는 concept_id 변형에서 가장 많이 떨어져요(−6.9%p).** 재료의 리터럴 형식을 베끼는 문제(하위 전개 67~82%)가 그대로라, 올바른 반영률이 62~74%에 머물러요. 학습 때 재료를 보여주는 효과(FT0 → FT1)는 변형에서도 확인돼요.
6. **base는 변형에서도 EX가 14~32%예요.** 하위 전개를 전혀 하지 않아(0%) 결과가 정답과 달라져요.
7. **SQL 재구성은 모델이 아니라 채점 방식을 시험해요.** 모델 입력이 원본과 같아서 모든 모델의 EX가 원본과 거의 같고(±1%p 이내), EM만 0%에 가까워져요. EX가 EM보다 신뢰할 만한 지표라는 근거예요.

  - 예: "…중 가장 먼저 도래하는 시점과 **그 사유를 집계**", "…시점을 **대상자별로 집계**하시오"처럼 패러프레이즈가 붙인 표현을 따라 정답에 없는 컬럼이나 집계를 추가했어요.

- **base+시스템 프롬프트(+4.6%p)와 base(+3.3%p)는 오히려 올랐어요.** 일부 패러프레이즈가 원문에 없던 반환 형식 힌트(예: "고관절 골절의 최초 발생일을 **환자별로 집계하여** 확인하라")를 붙여서 원본보다 쉬워진 문항이 있어요. 반환 형식을 질문만으로 알기 어려웠던 모델일수록 이 힌트의 덕을 봐요. FT2에는 같은 힌트가 오히려 혼란을 줬어요.

- **"학습 때 본 코드"와 "처음 보는 코드"의 EX 차이는 외운 효과만으로 해석하면 안 돼요.** 학습하지 않은 base+시스템 프롬프트도 72.0% vs 60.5%로 11.5%p 차이가 나요. 학습셋에 나오는 코드는 고혈압·심부전처럼 흔한 개념이 많아서 문항 자체가 쉬운 영향으로 보여요. 파인튜닝 모델의 차이는 FT1 8.4%p(76.3% vs 67.9%), FT2 6.9%p(96.2% vs 89.3%), FT0 3.9%p로 모두 이 기준선보다 작아서, 외운 효과로 볼 근거가 없어요.
- **랜덤화의 효과:** FT2는 concept_id 올바른 반영률 98.5%, 원본 대비 −1.6%p로 코드가 바뀌어도 거의 흔들리지 않아요. 다만 FT2는 학습량도 FT1의 3.6배라, 랜덤화 효과만 따로 떼어 보려면 FT1을 같은 학습량(epoch 늘림)으로 학습해 비교해야 해요.

## 5. 주의 사항

- **시스템 프롬프트 조건:** 모든 파인튜닝 모델과 base는 학습 때 문구로 평가했어요. Qwen 기본 문구로 평가한 FT0의 이전 변형 결과는 `results/adapter_eval/variant/adapter_eval_ft0_baseline_variant_*.csv`에 남아 있어요(EX 57.0% / 61.2% / 49.3% / 45.0%).
- **concept_id 변형의 새 코드 중 52%는 학습셋에도 나오는 코드예요.** 외워서 쓰는지 볼 때는 3.4절처럼 "학습 때 본 코드"와 "처음 보는 코드"를 나눠서 봐요.
- **모델 SQL 타임아웃(30초)과 정답 쿼리 실행 실패:** 다른 테스트와 같이 실패로 셌어요. `seed_422_test_concept`은 정답 쿼리 자체가 무거워서 다시 판정할 때도 DB 부하로 시간 초과가 났어요(base, FT0, FT2에서 실패로 셈). FT2는 paraphrase 1건도 같은 이유로 실패로 셌어요.

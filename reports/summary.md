# NL2SQL 어댑터 평가 — 핵심 요약

> 학습셋과 validation 셋 결과만 추려 정리한 문서입니다. 변형 테스트셋을 포함한 전체 결과와 지표 정의는 [00_overview.md](00_overview.md)에 있습니다.

## 목적

이 테스트의 목적은 두 가지입니다.

1. **베이스 모델과 파인튜닝 모델 비교:** 파인튜닝이 베이스 모델(프롬프트만 설계한 경우 포함) 대비 얼마나 나은지 확인합니다.
2. **파인튜닝 모델 간 데이터셋 구조 비교:** 학습 데이터의 구조(재료 포함 여부, concept_id 랜덤화 여부)에 따라 어떤 성능 지표에서 우위가 생기는지 확인합니다.

학습 데이터 구조 외의 조건(epoch, HPO trials, 체크포인트 선택 기준, 평가 시 시스템 프롬프트·재료·생성 설정)은 모두 동일하게 맞췄습니다.

## 비교한 모델

모든 모델은 같은 질문과 같은 **프롬프트(재료)**를 받습니다. 재료는 질문에 필요한 concept_id 후보, 사용할 수 있는 테이블·컬럼, 조인 방법을 정리한 텍스트입니다. 모델끼리 다른 점은 "학습할 때 무엇을 보았는가"와 "시스템 프롬프트"입니다.

| 모델 | 설명 |
|---|---|
| 프롬프트 미반영 학습 모델 | 질문과 정답 SQL만으로 파인튜닝한 모델입니다. 학습 때 재료를 보지 못했고, 평가 때만 재료를 받습니다. 재료를 넣어 학습하는 방식의 효과를 재기 위한 기준선입니다 |
| 프롬프트 반영 학습 모델 | 질문 + 재료 → 정답 SQL로 파인튜닝한 모델입니다. 학습 데이터 612건으로, 위 모델과 건수·정답 SQL·학습 조건이 같고 재료 유무만 다릅니다 |
| 프롬프트 반영 + 코드 랜덤화 학습 모델 | 위 학습 데이터에 concept_id만 무작위 코드로 바꾼 사본 3벌을 더해(총 2,202건) 파인튜닝한 모델입니다. 코드를 외우지 않고 재료에 적힌 코드를 옮겨 쓰도록 하려는 방식입니다 |
| 베이스 모델 | 파인튜닝하지 않은 원본 모델(`XiYanSQL-QwenCoder-14B-2504`)입니다 |
| 베이스 모델 + 규칙·예시 프롬프트 | 베이스 모델에 직접 설계한 긴 시스템 프롬프트를 붙인 것입니다. 하위 전개 규칙, PostgreSQL 문법 규칙, 정답 SQL 스타일 규칙과 예시 SQL 5개(few-shot)가 들어 있습니다. 파인튜닝 없이 프롬프트만으로 어디까지 되는지 보는 비교 대상입니다 |

- 파인튜닝 모델은 모두 1 epoch, 같은 HPO 조건(trials 5)으로 학습했고 eval_loss가 가장 낮은 체크포인트를 썼습니다.
- 파인튜닝 모델 셋과 베이스 모델은 학습 때 쓴 시스템 프롬프트("OMOP-CDM SQL 생성 전문가…, SQL만 출력")를 똑같이 받습니다.

| 프롬프트 반영 학습 모델 | 93.0% | 92.8% | 88.2% | 33.0% | 71.6% |

| 베이스 모델 | 91.5% | 0.0% | **96.7%** | 0.0% | 26.1% |
| 베이스 모델 + 규칙·예시 프롬프트 | 96.6% | 96.7% | 93.0% | 10.1% | 66.2% |

| 지표 | 의미 |
|---|---|
| 문법 유효성 | SQL 문법이 올바르고 테스트 DB에서 오류 없이 실행되는 문항 비율 |
| 하위 전개 | 대표 개념 코드(예: 고혈압)를 그 아래 세부 코드까지 포함하도록 `concept_ancestor`로 펼쳐 조회한 비율 |
| 프롬프트 반영도 | 정답 SQL에 필요한 concept_id를 모두 조건에 넣었고, 재료에 없는 테이블·컬럼을 쓰지 않은 문항 비율. 코드를 넣은 형식(하위 전개 여부)은 보지 않습니다 |
| EM | 정답 SQL과 문장이 글자 그대로 같은 비율. 결과가 같아도 작성 방식이 다르면 실패라 참고용입니다 |
| EX | 정답 SQL과 실행 결과가 같은 비율. **실제 정확도를 가장 잘 보여주는 지표입니다** |

- validation 셋 68건 중 5건은 "베이스 모델 + 규칙·예시 프롬프트"의 예시로 쓰여서 모든 모델에서 빼고 집계했습니다.

## 결론

1. **"프롬프트 반영 + 코드 랜덤화 학습 모델"이 가장 좋습니다.** EX가 학습셋 94.1%, validation 셋 92.1%로 다른 모델보다 17%p 이상 높습니다. 학습하지 않은 데이터에서도 점수가 거의 떨어지지 않았습니다. 변형 테스트셋 4종에서도 EX 90~97%로 가장 높았습니다([00_overview.md](00_overview.md)).
2. **학습할 때 재료를 같이 보여주면 정확도가 오릅니다.** 학습 데이터 건수가 같은 두 모델을 비교하면, 재료를 넣어 학습한 모델의 EX가 9~11%p 높습니다(학습셋 62.6% → 71.6%, validation 셋 63.5% → 74.6%).
3. **차이는 "코드를 찾는 능력"이 아니라 "코드를 정답 형식으로 옮기는 능력"에서 납니다.** 프롬프트 미반영 학습 모델도 필요한 코드는 비슷하게 넣지만(프롬프트 반영도 86~89%), 재료에 적힌 `IN (9202)` 형식을 그대로 베껴서 하위 전개를 26%가량 빠뜨리고 실행되지 않는 SQL도 많습니다(문법 유효성 83~87%).
4. **베이스 모델은 재료의 코드는 잘 넣지만 정답과 결과가 다릅니다.** 프롬프트 반영도는 가장 높지만(96~98%), 하위 전개를 전혀 하지 않아(0%) EX가 24~26%에 그칩니다.
5. **규칙·예시 프롬프트만으로도 베이스 모델이 크게 좋아지지만, 파인튜닝 모델에는 못 미칩니다.** EX가 베이스 모델 대비 약 40%p 올라 63~66%가 되지만, 프롬프트 반영 학습 모델(72~75%)과 랜덤화 학습 모델(92~94%)보다 낮습니다. 정답 SQL의 작성 방식은 따라 하지 못해 EM이 10% 안팎입니다.
6. **주의할 점:** 랜덤화 학습 모델은 데이터가 3.6배라 학습량도 그만큼 많았습니다. 향상이 랜덤화 덕분인지 학습량 덕분인지는 아직 구분할 수 없어서, 프롬프트 반영 학습 모델을 같은 학습량(약 4 epoch)으로 다시 학습해 비교할 예정입니다.
